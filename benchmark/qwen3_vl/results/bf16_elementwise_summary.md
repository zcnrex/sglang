# BF16 elementwise optimization outcome

Accepted production change: `bb52d02df4` (code PR commit `d7b4556d6b`). The SM103 BF16 SiLU-and-multiply launch for hidden width 9728 uses 128 threads, with vector width four for 1–32 tokens and eight for 33–128 tokens. Other shapes and configurations retain the existing launch. Precise arithmetic, BF16 rounding and PDL are unchanged. Final clang-format removed one blank line from the tested header; no semantic changes followed validation.

Independent standalone latency: B8 1.9915→1.1967 us, B16 1.9934→1.2200 us, B128 3.5934→3.0746 us. Exhaustive BF16 gates and special multipliers match bitwise; existing activation tests report 452 passed and 6 skipped. Full-model two-seed logits match bitwise at B1/8/16 with context 8192. B128 context 1024 matches bitwise after a startup-only diagnostic matches verified GEMM tactics and restores the public tuner before evaluation. The original independent-startup B128 comparison failed with different down-projection tactics; it is retained, not overwritten.

Normal-startup serving uses same-GPU swapped pairs on GPUs 6/7, BF16 weights/KV, mixed chunk 16384, HND page 32, TRT attention and fresh tuning caches. C1 N8/warm2 throughput improves 0.687% and 0.907% (geometric mean 0.797%); C8 N40/warm8 improves 0.087% and 0.445% (0.266%). C1 median TTFT increases 73.52→76.10 ms and 75.02→80.45 ms; TPOT decreases 2.352→2.333 ms and 2.362→2.335 ms. C8 TTFT decreases 364.46→362.36 ms and 360.13→358.84 ms; TPOT decreases 3.818→3.816 ms and 3.834→3.820 ms. These bounded screens complete exact request/token counts but do not establish general latency improvement or statistical noninferiority. Public M128 down tactics vary across startups.

C128 N128/warm128 normal-startup serving improves throughput by 0.230% and 0.189% (geometric mean 0.209%); median TTFT changes 4688.49→4628.70 ms and 4607.25→4684.09 ms, while TPOT changes 28.586→28.564 ms and 28.570→28.416 ms. Both pairs select different public M128 down-projection tactics (control/candidate: 1/4 and 6/4), so these results cannot isolate the activation change. All runs complete exact request/token counts; every server scores 19/20 on the short GSM8K sanity check. This is not a full accuracy evaluation.

Rejected normalization experiment: the faster Triton residual/RMSNorm implementation changes reduction order and full-model logits despite matching startup tactics. It is excluded from production. Arithmetic-preserving asynchronous-copy/PDL variants are flat or slower. The original unchunked B128/context8192 model diagnostic exhausted memory in both arms; context1024 was used for a separate diagnostic. This is not a production chunked-serving failure.

Evidence directories: `bf16_activation`, `bf16_activation_matched_model`, `bf16_elementwise_model`, `bf16_normalization`, `bf16_normalization_staging`, and `bf16_activation_serving`. Large model tensors remain remote with hashes; local traces, reports, source manifests and scripts preserve provenance. No new upstream benchmark or test files are included in the code PR. No recipe or cookbook change is needed.
