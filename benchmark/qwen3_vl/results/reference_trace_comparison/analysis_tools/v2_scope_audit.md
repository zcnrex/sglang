Read-only inspection of /root/qvl/venv-vllm-profile/lib/python3.12/site-packages/vllm/v1/worker/gpu/model_runner.py, the selected v2 runner. No kernel annotations or runtime cost estimates yet.

- execute_model starts1699. Request-state updates, staged block-table writes, dispatch/padding and prepare_inputs/prepare_attn precede actual decoder invocation. These can contribute GPU bookkeeping and must not silently count as decoder math.
- Around1780–1818, prepare_inputs copies input buffers, prepare_attn constructs block/slot mappings, model_state.preprocess_state handles relevant state (model-specific applicability must be checked).
- Around1845–1945, attention metadata and multimodal/model-input preparation precede graph/model dispatch. Fullgraph uses cudagraph_manager.run_fullgraph; PIECEWISE uses run_pw_graph; eager calls self.model. Capture metadata—not graph presence alone—determines actual mode.
- execute_model returns hidden states via ExecuteModelState, ending about2070. It does not execute the vocabulary projection on this default v2 path.
- sample_tokens begins2073 and invokes self.sample around2120. sample() starts1570; TP1 gathers hidden_states[input_batch.logits_indices], then self.model.compute_logits around1595, then sampler around1620. Therefore Worker.execute_model scope alone omits the vocabulary projection. A five-step profiler stopped there would also omit the fifth projection/sampling.
- sample_tokens also has optional grammar, prompt-logprob, connector and token-state updates; only observed enabled work belongs in the measured attribution.

Requested scope association: outer QVL_decode_stepN_BB_TB around execute_model; nested QVL_decoder_model_stepN_BB around actual run_pw_graph/run_fullgraph; QVL_decode_sample_stepN_BB around sample_tokens; nested QVL_compute_logits_stepN_BB around compute_logits. Compare decoder plus vocabulary projection union against the SGL model-forward contract, while separately reporting outer-only input bookkeeping, pre-projection hidden-state gather and post-projection sampler. Include all five sample phases when capture intends five complete cycles. No hostmonotonic-to-GPUclock conversion.

BF16 query/KV and TRTLLM generation backend were confirmed in startup logs by root. Startup reports PIECEWISE captures, which can coexist with FULL decode execution; only observed per-step dispatch metadata determines the measured graph mode.

Cache labels do not establish a per-layer kernel-layout difference. Pinned vllm/v1/kv_cache_layout.py defines logical [L,B,H,N,C], LBHNC=(0,1,2,3,4), and layer_view_order by removing the layer dimension and decrementing remaining indices. LBHNC therefore has per-layer [B,H,N,C] head-major block interiors, compatible with an HND description. flashinfer.py supported_kv_cache_layouts (around547) explicitly states that trtllm-gen consumes head-major block interiors and L/B nesting outside a block is immaterial. Runtime cache tensor shapes, strides, K/V packing and kernel view transformations remain pending; do not claim identical full strides or a layout performance difference from labels alone. Preserve cache allocation layout and per-layer kernel view separately in the comparison.

After transport recovery, pinned flashinfer.py2169 explicitly permutes by layer_view_order into HND. Lines2187–2203 state and implement BF16 K/V packed along the content dimension, then zero-copy split(head_size, dim=-1). Consequently K/V views retain packed parent strides even though axis ordering is HND. This can differ from separately allocated K/V stride magnitudes; actual runtime shape/stride evidence remains required before asserting the difference for these runs. utils.py184 get_flashinfer_layout_string maps allocator layout names to FlashInfer HND/NHD conventions.
