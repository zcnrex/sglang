# Reconstructed pinned vLLM profiling environment

The official wheel is pinned to commit `92044241a02f05de51420d654daf669de20b4691`, version `0.30.1rc1.dev648+g92044241a`. Its SHA256 is `357e6af0aa6a80e4cae8f5a825795bf9d873f599d3e3720b4ebeb23d5d83710b`. The isolated `/root/qvl/venv-vllm-profile` was installed from the included hashed lock, with Transformers 5.17.0. The original baseline's complete dependency lock was unavailable: this is a reconstructed environment. Existing SGLang and benchmark environments were not modified.

The launch preserves baseline defaults, including the resolved v2 runner, attention backend and graph policy. The checkpoint is pinned to `ebb281ec70b05090aa6165b016eac8ec08e71b17`. Logs resolve BF16 query, KV and model precision, TRTLLM generation attention and LBHNC cache layout. The label alone does not establish a different per-layer layout from SGLang HND.

The external observer changes no numerical operation. It wraps worker execution, v2 full/piecewise graph dispatch, and vocabulary projection. Profiling stops after the fifth associated sampling phase so the final vocabulary projection is retained. The offline analyzer separates decoder plus vocabulary projection from worker bookkeeping and sampling. The two native profiler exports retain their original `prefill_rank0` filename prefix; each completed run has `trace-mapping.json` with scope-derived phase and SHA256.

B8 and B16 ran on physical GPUs 4 and 5; B128 runs on GPU 4. SGLang uses different physical GPUs. Five profiled steps are sufficient for executed-kernel inspection, not a stable causal performance percentage. Only B128 has separately requested clock/power/temperature telemetry.

The initial v1-boundary startup attempts were stopped before capture after discovering that default v2 computes vocabulary logits during sampling. Corrected servers remained running when the initial accuracy client failed because its Python lacked SGLang. `resume.py.txt` reran the evaluator using the existing SGLang environment without restarting the healthy servers. Both completed 20-question checks scored 19/20. These failures and recovery are tooling limitations, not model failures.

B128 completed its separate sanity check at 18/20, then both capture stages. The `source_revision` in sanity metrics is the evaluator checkout revision (`466c9e0f`), not the vLLM runtime revision. Raw metrics are unchanged. All three decode captures contain five actual FULL graph executions; first-step mean sequence lengths are 8704.125 (B8), 8704.0625 (B16), and 8704.5078125 (B128). The B128 length range is 8673–8737, so matching the mean does not make the request-length distributions identical. The completed capture geometry and source-derived trace mapping are in `../vllm/capture-validation.json`.

GPU 4 and GPU 5 were verified empty (0 MiB, 0% utilization) after all owned servers completed. Foreign workloads on GPUs 0–3 were neither used nor interrupted. HTML sanity reports are losslessly gzip-compressed. The five installed source hashes cover the worker, v2 runner, profiler wrapper/config and FlashInfer attention backend. The public wheel URL and content hash are preserved in the hashed requirements lock.
