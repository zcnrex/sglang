# Remaining native subtile bottleneck audit (read-only)

No evidence-backed single-knob change currently supports a material additional gain. The measured FFI model gain remains small; reducing scratch allocation or blindly changing stage count would not establish a larger kernel improvement.

- **Full-width scratch:** the descriptor advertises M×19456 to preserve the original GEMM tile scheduler, but the epilogue stores only M×9728. Untouched-half NaN canaries verify this. Reducing the reserved allocation alone does not remove GPU writes or per-call allocation (model workspaces are already retained). A half-width public descriptor would require coordinated scheduler/coordinate changes without demonstrated traffic savings.
- **CTA wave utilization:** the persistent grid is 148 CTAs, 74 two-CTA clusters on 148 SMs. Logical M16331/N19456 at 256×256 gives 64×76=4864 cluster tiles: 65 complete rounds plus 54 tiles. Ideal final-wave loss is(66×74−4864)/(66×74)=0.41%, assuming equal tile work. M-tail waste is53/16384=0.32%. These arithmetic bounds are not measured utilization, but rule out a large gain from merely eliminating the tail. NCU's Waves Per SM=1 describes the persistent launch grid, not one logical output wave.
- **Shared-memory stages:** source _compute_stages fills the shared-memory budget at occupancy 1; measured dynamic shared memory is 229.63 KB/block. Two accumulator stages also reserve TMEM through _compute_num_tmem_alloc_cols. Simply reducing AB stages does not launch a second resident persistent block or reduce accumulator TMEM; enabling real two-block occupancy would require coordinated accumulator/pipeline/grid changes and may surrender overlap. No stall measurement currently shows excess AB stages as the bottleneck.
- **Paired weights/output stores:** once-interleaved gate/up weights preserve dense contiguous K rows and the same GEMM arithmetic. Subtile 128×64 eliminated all 1.63M spill requests;90 registers/thread and zero spills are now measured. There is no remaining reconstruction/copy operation in the steady-state kernel. Output still uses 128-bit stores. A 256-bit-store experiment would first require proving each paired output address has 32-byte alignment under the actual thread layout; current code only asserts 16-byte alignment. It could halve store instruction count, but current evidence does not quantify store issue as a material fraction, so this is not yet a justified performance experiment.

NCU reports memory pipes 95.13% busy, memory throughput 2.54 TB/s, max bandwidth 58.38%, L2 hit 69.52%, and no spills. Aggregate memory-pipe saturation does not distinguish operand TMA/shared-memory traffic, TMEM epilogue transfer, output stores, or stalls. It is insufficient to blame the output layout. The best next diagnostic, is a single focused instruction/stall attribution of the existing unchanged kernel, not another tile or stage sweep. Only dominant output-store issue would justify the narrowly bounded aligned256-bit-store variant; only a demonstrated operand pipeline stall would justify a pipeline-depth change.
