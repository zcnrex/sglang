# Pre-transformer metadata gap audit

Eight existing warmed component traces show 5.33–5.86 ms between the first preparation GPU kernel and first transformer GEMM. The union of GPU kernels, copies and memset in that interval occupies only 0.159–0.208 ms. Thus the earlier kernel-only gap is not principally uncounted copies. These are torch-profiler instrumented scripted-runtime forwards, not production idle-time measurements.

The largest contiguous gap is 2.19–2.45 ms immediately after `compute_position_kernel` and before a pageable host-to-device copy. All eight contain exactly 42 `aten::repeat` CPU calls in that gap, matching the B42 per-request MRoPE reconstruction. There are no CUDA synchronize or malloc API calls before the first GEMM in these traces. No compilation is evidenced. CPU operator tracing amplifies the repeated small-operation cost; the gap is not a promised uninstrumented saving.

Exact source path: `python/sglang/srt/model_executor/forward_batch_info.py`, `ForwardBatch.init_new` computes device `positions` using `compute_position` before `_compute_mrope_positions_extend`. The latter independently constructs each text request's CPU arange, repeats it three times, concatenates 42 pieces and copies to CUDA. Frozen remote `/root/qvl/sglang-prefix-production` has the same implementation (read directly). Its full source identity is retained in the component profile/model audit manifests.

Other pre-GEMM work is request allocation (`alloc_extend_kernel`), request-to-token mapping, pinned HtoD request/length lists, metadata foreach copies, context cumulative lengths and TRT block-table construction, packed-prefix CSR indexing, embedding gather and initial RMSNorm. `TRTLLMHAAttnBackend.init_forward_metadata` and `_init_packed_prefill_metadata` in `python/sglang/srt/layers/attention/trtllm_mha_backend.py` explain the post-MRoPE cumsum/arange/index kernels. They are not classified as removable or redundant from this trace alone. No Python stack capture was enabled, so attribution uses operation sequence plus exact source, not sampled stacks.

A bounded next experiment is an external ordinary-text-only MRoPE path that repeats the already-computed device int64 positions. It must retain the original branch for every multimodal object (including nonzero MRoPE deltas), speculative/custom positions and unsupported layouts. Compare exact integers for prefixes, chunks, mixed decode tails and zero-length rows, then the same B42/M16331 model/logits with unprofiled paired timing. This does not use prefill graphs or overlap. Standalone/model results belong in a separate subtree.

`gaps.json` preserves every pre-GEMM GPU operation and CPU operation counts. `analyze.py` reproduces the numbers from the committed component_profile gzip traces; their SHA manifest remains in that directory. No new GPU profiling or production edits were used for this audit.
