# BF16 activation launch validation

Candidate changes only the normal SiLU-and-multiply launch for SM103 BF16, hidden width 9728: 4 elements/thread and 128 threads through batch 32, 8 elements/thread and 128 threads through batch 128. All other cases retain the original launch. FP32 precise exp/division/multiply order, final BF16 rounding and PDL wait/trigger remain unchanged.

Immutable control: `/root/qvl/sglang-final-qkv-c76cfaba1a` (PR head c76cfaba1a1154a4a24b8694184cb8d3318fc358). Candidate: `/root/qvl/sglang-bf16-activation`. Final full manifest has 10,245 entries with exactly two intended activation source differences. Initial copy dereferenced two directory and two file symlinks; copies were preserved outside candidate and original symlinks restored before model admission. Runtime source did not change. Generated bytecode and pytest cache are excluded from source comparison.

Validation on GPUs 4/5: all 65,536 BF16 gate bit patterns with 11 up values including signed zeros, finite values, infinities and NaN are bitwise identical. Random initial and changed-input graph outputs also match bitwise across tested batches. Timing uses 36 disjoint layer inputs/outputs, retained CUDA graphs, GPU events, eight opposite-order rounds; 100 replays per round (4 at prefill 16384). This is activation-only latency, not a claim about full-model gains or dependency overlap. Full GEMM/activation/down dependency behavior is delegated to the independent actual-model gate.
