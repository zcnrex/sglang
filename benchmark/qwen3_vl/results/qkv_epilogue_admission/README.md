# Small-batch QKV epilogue fusion admission

This is a candidate rationale, not an implementation or speedup claim. Current M1/2/4/8 QKV projection uses FlashInfer cluster split-K tactic `(128,8,2,6)`, whose FP32 reduction already occurs inside the GEMM launch. It writes BF16 QKV, followed by the existing fused QK normalization/MRoPE/HND cache kernel. M16 is not on this mapped QKV path. There is no separate reduction launch to remove.

An external B8 prototype can retain GEMM/MMA/DSMEM reduction and move preparation into the owner CTA epilogue. Kernel-M128 spans one attention head and kernel-N8 spans eight tokens. It must preserve the initial BF16 conversion, normalization BF16 rounding, rotary BF16 multiply/FMA order and completion ordering until cache stores finish. The installed kernel exposes no callback, so an external clone requires argument and epilogue plumbing. No installed package or production file should change at this gate.

The existing real-model M8 trace records 36 preparation calls totaling 191.391 microseconds (median 5.312) and 36 immediately preceding QKV GEMMs totaling 287.492 microseconds (median 7.936), with consistent QKV grid `[48,2,1]`. Existing PDL overlap is substantial: QKV/preparation overlap totals 82.305 microseconds, and preparation/attention overlap totals 15.392. Exclusive preparation time is approximately 93.694 microseconds, before any added epilogue overhead. This diagnostic ceiling equals 2.65% of the separately measured unprofiled 3.532 ms graph; the profiled graph itself spans 4.298 ms, so it is not a speedup prediction.

Source references: installed `flashinfer/gemm/kernels/dense_bf16_gemm_sm100_splitk.py`, `SplitKDenseGemmKernel.epilog_warp` owner-rank output store; repository `python/sglang/kernels/jit/csrc/attention/fused_qk_norm_mrope.cuh`, `jit/include/sgl_kernel/impl/norm.cuh`, and `ops/attention/fused_qk_norm_mrope.py`. Trace source is `/root/qvl/experiments/lmhead-m8-diagnostic/m8/baseline-graph-trace.json` on the B300 host. Compact extraction and automated triage are retained here; automated recommendations are not validated conclusions.

Gate: standalone numerical/changed-input graph checks against current GEMM plus preparation, then paired cold-cache timings across distinct layer weights. A winning pair must also retain its advantage with representative attention and PDL dependencies. Text-position prototypes do not establish multimodal correctness. No model/serving run or production promotion is justified before these gates pass.
